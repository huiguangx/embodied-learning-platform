# EIP 具身智能训练平台：产品需求与开发设计

**版本**：v1.0  
**状态**：一期设计基线  
**范围**：训练平台；数据平台和仿真平台通过集成边界接入  
**证据来源**：已登录环境的只读页面采集，截图见 [`screenshots/eip-platform/README.md`](../screenshots/eip-platform/README.md)。

## 1. 摘要

EIP 要成为具身智能团队的统一 AI 研发与算力运营平台。用户从训练镜像、数据和资源准备开始，创建训练任务，沉淀可比较的实验与可复用模型，最终发布为在线服务；管理员则通过集群、队列、配额、预约和审计控制资源与成本。

一期不重建数据标注、仿真或底层 Kubernetes/对象存储能力，而是建立训练闭环及其统一控制面：

`资产 -> 资源治理 -> 开发/训练 -> 实验 -> 模型 -> 在线服务 -> 监控与审计`

## 3. 目标、非目标与成功标准

### 3.1 产品目标

1. 让算法工程师在一个控制台完成一次训练从资源选择到模型发布的主要操作。
2. 让管理员能基于队列、配额、预约和策略治理多集群 GPU，降低闲置与抢占冲突。
3. 让训练结果具备可追溯性：任一模型可以还原代码版本、镜像、数据版本、参数、资源和指标。
4. 让平台从“任务列表工具”升级为训练资产与服务交付平台。

### 3.2 非目标

- 不在一期实现数据标注、数据清洗、仿真场景编辑或底层集群编排。
- 不自研容器镜像仓库、对象存储、指标时序库或 Kubernetes 调度器。
- 不支持无审批的跨租户资产共享和生产级多地域容灾。

### 3.3 一期验收指标

| 指标 | 目标 |
| --- | --- |
| 训练可追溯率 | 100% 已完成训练可关联镜像、代码版本、数据版本、资源、参数和产物。 |
| 训练提交效率 | 常规任务从模板创建到提交不超过 10 分钟。 |
| 资源治理覆盖 | 100% GPU 任务进入资源组和队列，超额请求被拒绝或排队。 |
| 实验沉淀 | 100% 训练自动生成实验运行记录；用户可比较至少 3 次运行。 |
| 发布链路 | 已入库模型可一键创建推理服务并展示运行状态、版本和基础指标。 |

## 4. 用户与权限

| 角色 | 主要目标 | 权限边界 |
| --- | --- | --- |
| 算法工程师 | 创建开发机、训练、实验比较、模型发布 | 管理本人及被授予项目的任务、模型和服务；只可使用获授权的资源组。 |
| 数据工程师 | 准备数据集、维护版本、授权训练使用 | 管理所属数据集及对象存储逻辑路径；不可直接修改他人训练任务。 |
| 平台运维 | 维护集群、节点、队列、资源组和服务运行 | 管理全局资源与运行状态，不得修改用户代码或数据内容。 |
| 业务管理员 | 项目、成员、预算、审批和审计 | 管理组织级授权、配额与审批，可查看范围内成本和活动。 |

权限模型采用 `组织 -> 项目空间 -> 资源组 -> 资源对象` 四层 RBAC。所有写操作必须记录操作者、项目、对象、前后状态与请求 ID。

## 5. 核心业务流程

### 5.1 训练闭环

1. 用户进入首页，确认目标集群状态和 GPU 负载。
2. 在资产中心选择训练镜像；在数据平台或对象存储选择已版本化的数据集；创建或选择代码版本。
3. 在资源页选择项目资源组、队列、优先级和可用预约时段。
4. 从任务模板创建训练，填写参数、分布式规格、输入/输出路径和检查点策略；提交后获得任务 ID。
5. 调度服务校验配额、镜像/数据权限及集群能力，进入排队、运行、成功、失败或已取消状态。
6. 运行时采集日志、资源使用、指标、检查点和产物；自动创建实验运行记录。
7. 用户在实验管理中筛选、比较、标记最佳运行，并将选定产物注册为模型版本。
8. 用户从模型仓库创建在线服务，平台部署推理版本、健康检查并展示流量、延迟、错误率和实例状态。

### 5.2 开发机流程

用户选择镜像、资源组、集群、GPU/CPU/内存和云盘创建开发机；平台在授权资源内启动实例。用户连接 IDE/Jupyter 后可选择“从当前环境生成训练模板”。空闲超时、到期或用户停止时回收计算资源，云盘按策略保留。

### 5.3 资源治理流程

管理员维护资源组及其成员、集群范围、GPU/CPU/内存配额、并发数、默认队列和预算标签。队列按优先级、预约窗口、项目权重和公平共享调度；不可满足的任务返回明确的排队原因和预计等待信息，而不是静默失败。

## 6. 产品需求

### P0：统一项目与资产引用

**需求**：所有训练、实验、模型、服务必须归属项目空间，并通过不可变版本引用镜像、代码和数据。

**验收**：

- 创建训练时只能选择用户有权限的镜像、数据集、代码版本和资源组。
- 删除、变更“当前版本”不影响历史训练复现；历史对象保留版本 ID 与摘要。
- 对象存储页保留文件浏览职责；训练表单引用“数据集版本”，不直接依赖人工输入路径。

### P0：资源组、队列与预约

**资源组**：项目成员、集群范围、可用节点类型、CPU/内存/GPU 配额、最大任务数、成本中心。  
**队列**：资源组归属、优先级、并发、抢占策略、最大运行时长和调度权重。  
**预约**：资源组、节点/GPU 类型、开始结束时间、容量、受益成员和审批状态。

**验收**：超配请求可预检并显示缺少的资源；预约窗口内保留容量；队列页显示运行、排队、预计可用和拒绝原因。

### P0：训练任务

训练表单分为五步：基础信息、代码与运行环境、数据与输出、资源与调度、参数与确认。支持任务模板、草稿、复制和停止；不允许运行中编辑不可变配置。

状态机：`草稿 -> 待校验 -> 排队 -> 分配中 -> 运行中 -> 成功 | 失败 | 已取消 | 已停止 | 超时`。允许从失败/成功任务“克隆配置”创建新任务，但不复用旧任务 ID。

### P0：实验管理

每次训练自动产生 `ExperimentRun`。用户可为运行补充名称、标签、备注，记录超参数、指标曲线、日志、资源消耗、产物和关联任务；可多选运行比较参数与指标，标记一个或多个“候选最佳”。

### P0：模型仓库

模型版本由实验运行产物注册，包含框架、格式、签名、大小、指标摘要、依赖镜像、数据/代码来源、审批状态和生命周期。状态机：`草稿 -> 待审批 -> 已发布 -> 已弃用 -> 已归档`。生产发布只允许已发布模型。

### P0：在线服务

服务由模型版本、推理镜像、资源规格、环境配置和网络策略组成。支持创建、查看、停止、删除和版本切换；一期提供滚动更新，灰度流量、自动扩缩容和 A/B 测试列为后续迭代。

### P1：可观测性与成本

首页保留现有集群概览，新增项目和任务维度的 GPU 时间、排队时间、成功率、失败原因、显存使用、服务延迟/错误率及成本估算。数据默认按项目隔离。

### P1：审批与通知

需要审批的动作：超配资源、预约、模型发布到生产、服务公开暴露。支持站内通知；失败、长时间排队、预约开始/结束和服务异常必须通知相关用户。

## 8. 技术架构

### 8.1 分层

```text
Web Console
  -> BFF / API Gateway
      -> Identity & Project Service
      -> Asset Catalog Service
      -> Resource Governance Service
      -> Training Orchestrator
      -> Experiment & Model Registry
      -> Serving Controller
      -> Notification & Audit Service
      -> Observability Query Service

Integration Adapters
  -> Kubernetes / Scheduler, Container Registry, Object Storage,
     Git provider, Metrics/Logs, Data Platform, Simulation Platform
```

前端只调用 BFF；BFF 负责鉴权、项目上下文和聚合，禁止前端直连集群、对象存储管理接口或内部编排服务。领域服务通过事件总线传播异步状态，读模型可按项目维度缓存。

### 8.2 服务职责

| 服务 | 职责 | 不承担 |
| --- | --- | --- |
| Identity & Project | SSO 映射、项目、成员、RBAC | 集群资源调度。 |
| Asset Catalog | 镜像、数据集、代码、模型的版本索引和授权 | 存储真实大文件。 |
| Resource Governance | 配额、资源组、队列、预约、预检 | 实际容器生命周期。 |
| Training Orchestrator | 任务状态机、模板、编排请求、取消和重试 | 保存实验指标。 |
| Experiment & Model Registry | 实验运行、指标、产物、模型审批与版本 | 部署服务实例。 |
| Serving Controller | 服务部署、版本切换、健康状态 | 训练编排。 |
| Audit & Notification | 不可变审计、订阅、通知投递 | 业务状态主存储。 |

### 8.3 外部集成与故障边界

- Kubernetes/调度器：通过适配器提交 Job、Pod 或服务 CR；平台持有幂等提交键，回调乱序时按资源版本和状态机拒绝回退。
- 对象存储：以短期签名 URL 或平台代理访问；平台只存 URI、版本、校验和和元数据，不转存大文件。
- 镜像仓库：只读发现和权限校验；镜像必须以 digest 固定，不能以可变 tag 作为复现依据。
- 指标/日志：采集任务、容器、服务标签，统一附加项目、任务、实验和服务 ID。
- 数据/仿真平台：以数据集版本、仿真任务版本和产物 URI 交换；双向调用均使用服务身份和项目授权。

## 9. 关键数据模型

| 实体 | 关键字段 |
| --- | --- |
| Project | id、组织、名称、成员、成本中心、状态。 |
| ResourceGroup | projectId、集群范围、节点类型、CPU/内存/GPU 配额、并发、预算标签。 |
| Queue | resourceGroupId、优先级、权重、并发、最大时长、调度策略。 |
| Reservation | resourceGroupId、资源规格、起止时间、容量、审批状态。 |
| AssetVersion | assetType、名称、版本、digest/checksum、URI、权限、来源。 |
| TrainingJob | projectId、templateVersion、imageDigest、codeVersion、datasetVersion、resourceRequest、queueId、状态、输出 URI。 |
| ExperimentRun | trainingJobId、指标、参数、日志 URI、产物 URI、最佳标记。 |
| ModelVersion | experimentRunId、格式、签名、指标摘要、审批状态、生命周期。 |
| OnlineService | projectId、modelVersionId、镜像 digest、资源规格、端点、状态、版本策略。 |
| AuditEvent | actor、projectId、resourceType、resourceId、action、before/after、requestId、时间。 |

关系要求：`TrainingJob` 固定引用多个 `AssetVersion`；`ExperimentRun` 一对一关联首次训练，可聚合多个重跑；`ModelVersion` 必须能回溯到 `ExperimentRun`；`OnlineService` 固定到一个 `ModelVersion`。

## 10. API 设计原则与核心接口

API 使用 REST/JSON，路径均带项目上下文：`/api/v1/projects/{projectId}/...`。写操作接受 `Idempotency-Key`，返回 `requestId`；异步操作返回 `202 + operationId`；列表使用 cursor 分页并支持服务端筛选。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/dashboard` | 项目或全局汇总指标。 |
| GET/POST | `/resource-groups` | 查询/创建资源组。 |
| GET/POST | `/queues`、`/reservations` | 队列与预约。 |
| POST | `/training-jobs:validate` | 提交前权限、配额、镜像、数据和参数预检。 |
| GET/POST | `/training-jobs` | 任务列表、创建任务。 |
| POST | `/training-jobs/{id}:cancel` | 请求停止；异步返回最终状态。 |
| GET | `/experiment-runs` | 列表、筛选、比较数据。 |
| POST | `/model-versions` | 从实验产物注册模型。 |
| POST | `/online-services` | 创建推理服务。 |
| GET | `/audit-events` | 管理员按项目、对象和操作者检索审计。 |

错误统一为 `code`、`message`、`requestId`、`details`。例如 `QUOTA_EXCEEDED` 必须带缺少资源与可选队列；`ASSET_ACCESS_DENIED` 不泄露无权资产细节。

## 11. 安全、可靠性与合规

- SSO 登录，服务间使用短期凭据；不在任务参数、日志和审计中记录密钥。
- 所有对象存储、镜像、数据和模型访问按项目授权，URL 使用短期签名。
- 训练和服务执行环境默认最小权限、网络隔离、非 root、镜像扫描和准入策略。
- 审计日志追加写、可检索、不可由普通用户删除；保留周期由组织策略配置。
- 状态回调、取消、注册和部署均实现幂等；调度器不可用时任务保持“分配中/排队”并指数退避重试。
- 任务失败显示可行动原因：资源不足、镜像拉取、权限、用户代码、平台基础设施五类。

## 12. 分期与交付顺序

| 阶段 | 范围 | 完成定义 |
| --- | --- | --- |
| 0：夯实基础 | 项目 RBAC、审计、资产版本统一、任务状态机 | 历史与新训练可以完整追溯。 |
| 1：训练闭环 | 资源组/队列/预约、训练向导与模板、实验管理、模型仓库、服务最小发布 | 用户可在 UI 完成训练到在线服务的闭环。 |
| 2：治理与效率 | 成本、审批、通知、任务比较增强、服务监控与滚动更新 | 管理员可基于数据控制使用与成本。 |
| 3：智能化 | 弹性任务、自动扩缩、灰度发布、推荐资源规格、仿真联动 | 面向规模化运营优化。 |

## 13. 验收场景

1. 算法工程师选择指定镜像、数据集版本、资源组和队列，成功提交训练；详情显示所有固定引用。
2. 配额不足时预检失败，页面显示限制来源与替代队列，且不创建半成品任务。
3. 任务完成后自动出现实验运行、指标与产物；用户选择该运行注册模型，模型可回溯任务。
4. 已发布模型可创建在线服务，页面显示部署状态、端点、实例和基础延迟/错误率。
5. 管理员变更资源组配额、审批预约、查看审计；普通用户无法读取其他项目资产或操作记录。
6. 集群回调重复或乱序时，任务最终状态不倒退、不重复创建实验或模型。

## 14. 风险与决策

| 风险 | 应对 |
| --- | --- |
| 多集群资源语义不一致 | 以统一资源规格描述，集群适配器负责映射并在预检时返回能力差异。 |
| 任务、实验、模型元数据断链 | 将版本引用设为创建训练的必填项，禁止以可变 tag/裸路径发布。 |
| 训练任务状态不可靠 | 用事件幂等键、状态机和定时对账修正外部回调。 |
| 资产权限旁路 | BFF 与外部适配器双层授权，短期凭据按项目签发。 |
| 一期范围膨胀 | 以“闭环可用”验收；弹性调度、灰度、A/B、全功能仿真均进入后续阶段。 |
